ホルンれんしゅう v0.6.2（GitHub Pages公開用・試験版）
作成日: 2026-11-19

【何をするアプリか】
紙の楽譜をスマホなどで撮影・選択すると、読譜エンジンが音符・休符・音の長さをMusicXMLに変換し、
実際のホルンに近いサンプル音源で演奏することを目指したアプリです。
v0.6.2から複数枚の楽譜写真を1曲として扱えます。

【複数ページの使い方】
1. 「がくふを 追加・とる」から写真を選びます。端末が対応していれば複数枚をまとめて選択できます。
2. カメラで1枚ずつ撮る場合は、同じボタンから後のページを追加します。
3. ページ一覧の ↑ ↓ で順番を確認・変更できます。×で不要ページを削除できます。
4. 複数ページでは「この順で 全部よむ」を押します。
5. スマホの負荷を抑えるため、同時には解析せず1ページずつ順番に読み取ります。
6. 全ページが読めたら、小節番号と再生時刻をつなぎ直して1曲として連続再生します。
7. 読み取りに失敗したページがある場合は、そのページだけ再試行できます。
8. PDFは1ファイルとして読譜エンジンへ渡します。PDF内部の複数ページは読譜エンジン側で処理されます。

【原譜との確認】
・認識結果は100%ではありません。すべての読譜結果で原譜との比較を必須にしています。
・複数ページでは確認するページを選び「このページを表示」を押すと、そのページを再読込して確認・修正できます。
・修正した場合は「なおした音を演奏に反映する」を押すと、そのページのMusicXMLを更新し、曲全体を再構成します。
・全ページを確認した後で「すべてのページを、もとの楽譜と見比べました」にチェックすると再生できます。

【GitHub公開方法】
1. ZIPを解凍し、index.html / app.js / sw.js / horn フォルダ等、中身を全てアップロードしてください。
2. GitHubの Add file → Upload files → Commit changes で既存のHORUNNリポジトリへ上書きします。
3. Settings → Pages → Build and deployment は従来どおり main / (root) のままで構いません。
4. 公開URLを更新するとv0.6.2が表示されます。古い表示が残る場合はブラウザを再読込してください。
5. 最初の楽譜読取時は読譜エンジンとモデルをオンライン取得します（約150MB＋実行用ライブラリ）。

【v0.6.2 複数ページ対応】
・写真ファイルの複数選択と、後からの追加に対応。
・サムネイル付きページ一覧を追加。
・↑↓によるページ順変更、個別削除、全削除に対応。
・複数ページは1ページずつ順番に解析し、進捗を「1 / 4ページ」のように表示。
・解析済みページは再解析せず、追加したページだけ後から読める構成。
・ページごとのMusicXMLを保持し、全ページを連続した小節・拍位置へ安全に連結。
・後ページにテンポ記号がない場合、ページごとに仮テンポ120へ戻らず前ページのテンポを継続。
・ページ別の警告と低解像度警告に対応。
・失敗ページだけ再試行可能。
・複数ページの確認・修正後、曲全体へ再反映可能。
・再生時のテンポ配列をコピーしてから倍率調整するよう修正し、複数回再生でテンポ倍率が累積する問題を防止。

【v0.5.2 読譜停止対策】
・認識後のMusicXMLを、読譜エンジン側の画面状態に依存せず検出するよう修正。
・読譜エンジン内部のJavaScriptエラー/Promiseエラー/画面上エラーをHORUNN側へ表示。
・写真が読譜エンジンへ渡せたかを直後に確認。
・初回約150MBのモデル取得中であることを明示。
・8分で完了しない場合は無期限に待たず、通信・空きメモリ確認を促すエラーへ移行。

【注意点と確認の限界】
・音符の認識精度は100%ではありません。認識結果が不正確だと再生も不正確になります。
・テンポ変更、連符、休符、タイはMusicXMLに書かれた拍数・音価情報から演奏します。
・強弱、アーティキュレーション、スラーの表情、複雑な反復は再現できません。
・複数パートでは先頭のパートを演奏します。ホルンソロ向けです。
・F管ホルンでは原則として楽譜より完全5度低い音を鳴らします。
・ページを別々に読譜するため、ページ境界をまたぐタイなどは読譜エンジンが別ページへ分割した状態では完全には結合できない場合があります。
・冒頭にテンポの指定がない場合は仮に♩=120で再生します。2ページ目以降でテンポが読めないだけの場合は、前ページのテンポを継続します。
・実機や写真条件により認識時間・メモリ使用量は変わります。現段階は試験版です。
